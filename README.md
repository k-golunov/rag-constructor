# RAG Constructor

RAG Constructor — конструктор ассистентов, которые отвечают на вопросы по загруженным документам. В одном интерфейсе можно настроить модели и поиск, проверить ответы в чате и сравнить несколько конфигураций на одном наборе вопросов.

## Возможности

- **Проекты.** Настройка OpenAI-совместимых провайдеров для генерации и эмбеддингов, системного промпта, размера и перекрытия чанков, числа результатов поиска (`top_k`) и лимита контекста.
- **Документы и поиск.** Загрузка TXT, DOCX и PDF с текстовым слоем, в том числе в ZIP-архивах. Приложение извлекает текст, разбивает его на фрагменты и индексирует эмбеддинги в Qdrant. Версии документов, настроек и индексов помогают связать ответы с условиями прогона.
- **Чат.** Ответы с найденными источниками, история диалога и трасса выполнения. Ошибка поиска прерывает запрос. Если поиск отработал, но не нашёл фрагментов, модель может ответить без контекста из документов.
- **Эксперименты.** Версионируемые наборы вопросов с эталонами и свидетельствами, разделение на `tuning` и `test`, пакетное сравнение вариантов конфигурации с повторами. Фоновые прогоны показывают прогресс и поддерживают отмену и продолжение.
- **Оценка.** Ручная проверка ответов и анализ результатов прогонов. Встроенный `transport_stub` проверяет передачу данных в оценщик. Автоматическая оценка качества ответов пока не реализована.

OCR, загрузка HTML и CSV, локальные модели эмбеддингов и потоковая выдача ответов пока не поддерживаются.

## Технологии

| Компонент | Стек |
| --- | --- |
| Интерфейс | Angular 21, TypeScript, RxJS. В контейнере приложение отдаёт Nginx |
| API и данные | Python 3.12 в Docker и CI, FastAPI, Uvicorn, Pydantic, SQLAlchemy, Alembic, PostgreSQL 15 |
| Обработка документов и RAG | pypdf, python-docx, LangChain Text Splitters, OpenAI Python SDK для вызова совместимых API, Qdrant для векторного поиска |
| Фоновые задачи | Celery и Redis. Celery Beat планирует повторную отправку сохранённых в PostgreSQL заданий |
| Окружение и проверки | Docker Compose, Poetry, npm, pre-commit, Ruff, Black, pytest и Vitest. Конфигурации CI хранятся в [GitHub Actions](.github/workflows/ci.yml) и [Jenkinsfile](Jenkinsfile) |

## Быстрый запуск

Для полного стека нужен Docker с Compose. Из корня репозитория скопируйте `.env.example` в `.env` и запустите контейнеры.

```bash
cp .env.example .env
docker compose up --build -d
```

В PowerShell вместо `cp .env.example .env` можно использовать `Copy-Item .env.example .env`.

1. Откройте [интерфейс](http://localhost:4200) и создайте проект.
2. Укажите модели генерации и эмбеддингов, ключи и при необходимости URL провайдеров. Размерность эмбеддингов должна совпадать с выбранной моделью. Общий запасной ключ можно задать в `OPENAI_API_KEY` в `.env`.
3. Загрузите документ, дождитесь статуса `completed` и задайте вопрос во вкладке чата.

API доступен на стандартном порту 8000. Откройте [Swagger UI](http://127.0.0.1:8000/docs) или [схему OpenAPI](http://127.0.0.1:8000/openapi.json). При запуске API пытается применить миграции Alembic. Если интерфейс открывается, а проекты не загружаются, проверьте журнал `docker compose logs backend`.

Эти команды рассчитаны на запуск на своём компьютере. Собранный интерфейс обращается к `127.0.0.1:8000` из браузера. Для доступа с другой машины нужно настроить адрес API и проксирование.

Для разработки с автообновлением кода можно поднять только инфраструктуру в Docker, а API и интерфейс запустить на машине. Нужны Python 3.12, Poetry и Node.js с npm (образ frontend использует Node.js 20.19). Для фоновых пакетов используйте полный Compose или отдельно запустите worker и планировщик по [инструкции](docs/background-execution.md).

```bash
docker compose up -d postgres qdrant redis
poetry install
poetry run uvicorn backend.main:app --reload
```

В другом терминале из корня:

```bash
cd frontend
npm install --legacy-peer-deps
npm start
```

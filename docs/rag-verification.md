# Проверка полного RAG

Для эксперимента используйте `POST /api/v1/public/provider/projects/{id}/chat`
с телом `{"question": "Какой код доступа к архиву проекта Север?"}`.
`/chat/generate` принимает готовый контекст и **не проверяет поиск**.

Результаты поиска различаются так:

| Результат | HTTP | Поле | Генерация и история |
| --- | --- | --- | --- |
| Найден непустой контекст | 200 | `retrieval_status: success` | LLM получает контекст, вопрос и ответ сохраняются |
| Поиск выполнен, подходящих фрагментов нет | 200 | `retrieval_status: no_context` | Генерация с пустым контекстом; не считать подтверждением RAG |
| Сбой Qdrant, отсутствующая коллекция, ошибка эмбеддера или размерности | 502 | `detail.status: error`, `detail.retrieval_status: error`, `detail.code: retrieval_error` | LLM не вызывается, успешный ответ не сохраняется |

Внешний обработчик эксперимента должен записывать HTTP 502 как ошибку примера.
Принятые попытки сохраняют настройки и статус во внутреннем журнале `execution_runs`.
В API отключён прежний переход к генерации после ошибки поиска для всех запросов `/chat`.

Опциональный `score_threshold` в запросе `/chat` задаёт минимальную косинусную
близость (-1…1). Без него выбираются ближайшие фрагменты без порога;
наличие результата само по себе не доказывает смысловую релевантность.
Порог нужно подбирать для используемой модели на контрольных вопросах.
При несовпадении размерностей существующая коллекция не пересоздаётся:
исправьте настройки или используйте новый проект с повторной загрузкой.

## Настройки для анализа метрик

`top_k` (1…100, по умолчанию 5) и `max_context_chars` (1…100000, по умолчанию
2000) сохраняются в проекте и доступны в формах создания и редактирования.
Их можно переопределить для отдельного запроса `/chat`, не меняя проект:

```json
{
  "question": "Какой код доступа к архиву проекта Север?",
  "top_k": 3,
  "max_context_chars": 6000,
  "score_threshold": 0.5
}
```

Лимит контекста измеряется в символах найденного текста, включая разделители.
Системный промпт, история и вопрос в этот лимит не входят. `top_k` ограничивает
поисковую выдачу; лимит контекста может уменьшить число фрагментов, переданных
модели. `sources` перечисляет только источники фактически переданного текста.

Ответ `/chat` содержит `applied_settings` и фактический `context_chars`.
У сообщения ассистента в SQL-истории сохраняется `rag_metadata`: статус поиска,
снимок настроек проекта и переопределений запроса, переданный контекст,
найденные фрагменты с метаданными и идентификаторы фрагментов контекста.
API-ключи в этот снимок не включаются. Последующее изменение проекта не меняет
уже сохранённый снимок. При ошибке retrieval снимок есть в `detail.applied_settings`;
успешная пара сообщений не сохраняется.

При новой индексации метаданные фрагментов содержат реальные `index_settings`
(размер чанка, перекрытие, стратегия), модель и размерность эмбеддинга.
Изменение параметров чанкинга или эмбеддера теперь выбирает либо строит
отдельную версию индекса из сохранённых файлов. Генеративные и поисковые
параметры используют прежний индекс повторно. Старые источники без
`document_version_id` нужно загрузить заново перед анализом.
Подробности — [версии документов и индексов](versioning.md).

Неподдерживаемые оси сравнения запрещены в API и недоступны в формах:

- `split_by`: разрешено только `paragraphs`, обозначающее существующий
  рекурсивный алгоритм с последовательностью разделителей. Отдельные режимы
  `sentences` и `tokens` не реализованы и возвращают 422.
- `chunking_strategy`: только `recursive`.
- `extract_tables`: только `false`, переключение извлечения PDF-таблиц пока
  не реализовано.
- Неизвестные поля проекта и запроса `/chat` (например, `temperature`)
  возвращают 422 вместо молчаливого игнорирования.

Проверка `chunk_overlap < chunk_size` выполняется при создании проекта, для
итоговых значений после частичного PATCH и повторно в самом сплиттере.
Некорректный PATCH не сохраняет никаких изменений. Старый проект с
неподдерживаемыми параметрами не допускается к загрузке и `/chat`, пока
настройки не исправлены.

Для существующей БД добавлена миграция `0003`: новые настройки проекта с
дефолтами 5/2000 и JSON-поле `chat_history.rag_metadata`. Она применяется
стандартной инициализацией backend при запуске. Перед запуском обновлённого
приложения убедитесь, что миграция завершилась успешно.

Миграция `0004` добавляет журнал настроек и статусов всех принятых попыток,
включая ошибки и `/chat/generate`. Ответы обоих маршрутов возвращают `run_id`,
`applied_settings`, `context_chars`; ошибки выполнения содержат идентификатор
и настройки в `detail`. Подробности и правила сравнения — в
[описании настроек выполнения](execution-settings.md).

## Автоматическая проверка

Из корня репозитория:

```powershell
backend/.venv/Scripts/python.exe -m pytest backend/tests/test_rag_pipeline.py -p no:asyncio -q
```

Тест загружает `backend/tests/fixtures/rag_control.txt` через API, индексирует
его в настоящем локальном движке Qdrant, добавляет отвлекающий документ,
находит контрольный фрагмент и проверяет его присутствие в сообщениях LLM.
Затем проверяет ответ и сохранённую SQL-историю через API.
Внешние ответы эмбеддера и LLM детерминированно подменены; качество реальных
моделей этот тест не оценивает. База SQLite и каталог загрузки изолированы,
инициализация PostgreSQL в тестах отключена.

Дополнительно проверяются пустая выдача, порог релевантности, недоступность
Qdrant, отсутствующая коллекция, несовпадение размерностей коллекции/проекта/
векторов и некорректное количество эмбеддингов. При ошибке поиска проверяется,
что генерация не запускается и история не пополняется.

Можно запустить те же тесты с сервером Qdrant (уникальные тестовые коллекции
создаются и удаляются автоматически):

```powershell
$env:QDRANT_TEST_URL = 'http://localhost:6333'
backend/.venv/Scripts/python.exe -m pytest backend/tests/test_rag_pipeline.py -p no:asyncio -q
Remove-Item Env:QDRANT_TEST_URL
```

## Ручная проверка с реальными моделями

1. Запустите стек и создайте отдельный контрольный проект. Укажите доступные
   эмбеддер и LLM, их ключи и URL. Размерность проекта должна совпадать с
   фактическим размером ответа эмбеддера.
2. Загрузите `backend/tests/fixtures/rag_control.txt` через интерфейс или
   `POST /api/v1/public/provider/upload/single?project_id={id}` (multipart,
   поле `file`). Убедитесь в `status: completed`, `chunks_count > 0`.
3. Спросите «Какой код доступа к архиву проекта Север?» через `/chat`.
   В ответе ожидаются `retrieval_status: success`, источник `rag_control.txt`
   и код **КЕДР-7429**. Через `GET /api/v1/public/provider/projects/{id}/chat/{session_id}`
   проверьте сохранённые вопрос и ответ. Ответы API удобно смотреть во вкладке
   Network инструментов разработчика браузера.
4. Остановите только Qdrant (`docker compose stop qdrant`) и повторите вопрос.
   Ожидаются HTTP 502 и `detail.retrieval_status: error`; интерфейс показывает
   сообщение об ошибке. В истории не должно появиться нового ответа.
5. Верните Qdrant (`docker compose start qdrant`) и повторите вопрос:
   успешный ответ с источником должен восстановиться.

Ручной сценарий проверяет реальные модели и серверные подключения, дополняя
изолированный автоматический тест.

- Backend: 152 теста прошли, включая 25 проверок в `test_rag_pipeline.py`,
  20 проверок в `test_rag_settings.py`, 12 проверок в `test_execution_runs.py`

  и 29 проверок в `test_question_sets.py`.

  отключена из-за несовпадения установленных версий pytest и pytest-asyncio.
- Black и Flake8 для изменённых Python-файлов: без замечаний.
- TypeScript и Angular-шаблоны: `ngc -p tsconfig.app.json --noEmit` прошёл.
- Проверен SQL миграции `0002 → 0003` для PostgreSQL; добавление полей,
  дефолты существующих строк и откат проверены на временной SQLite.
- Для миграции `0003 → 0004` также проверены PostgreSQL SQL и создание/откат
  внутреннего журнала на SQLite.
- Для `0004 → 0005` проверены PostgreSQL SQL, создание/откат таблиц версий
  и внешние ключи на SQLite.
- Для `0005 → 0006` проверены PostgreSQL SQL, создание/откат поля трассы и
  сохранение `null` для старых записей на SQLite.
- Для `0006 → 0007` проверены PostgreSQL SQL, создание/откат наборов вопросов,

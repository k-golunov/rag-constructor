# Явные настройки выполнения

## Выполненные пункты

| Требование | Реализация |
| --- | --- |
| Настройка `top_k` | Проект, формы создания/редактирования, переопределение для одного `/chat`; 1…100, по умолчанию 5 |
| Явный лимит контекста | `max_context_chars`; 1…100000, по умолчанию 2000; проект и оба маршрута генерации |
| Проверка перекрытия | `chunk_overlap < chunk_size` при создании, частичном обновлении, в форме и сплиттере |
| Недоступные параметры отмечены | `unsupported_parameters` с объяснениями; `comparison_parameters` перечисляет допустимые оси сравнения |
| Настройки сохраняются | `execution_runs.applied_settings` для каждой принятой попытки, включая технические ошибки |

## Что возвращает API

`POST /api/v1/public/provider/projects/{id}/chat` выполняет полный RAG.
`POST /api/v1/public/provider/projects/{id}/chat/generate` работает по переданному
контексту и не выполняет поиск. Оба маршрута возвращают `run_id`,
`applied_settings` и фактический `context_chars`. Технические ошибки возвращают
HTTP 502 со статусом `error`, кодом, `run_id` и `applied_settings` внутри `detail`.

Настройки поиска включают `top_k`, порог близости, коллекцию, модель эмбеддингов,
размерность и провайдера. Настройки генерации включают модель, фактически
выбранный системный промпт, лимит контекста и режим без стриминга. Адреса
провайдеров сохраняются без userinfo, query и fragment. Ключи API не сохраняются.
Fallback URL из конфигурации и стандартный системный промпт учитываются
одинаково в снимке и при создании адаптера.

Лимит применяется только к тексту контекста, включая разделители, и измеряется
в символах. Системный промпт, вопрос, история и длина ответа — отдельные величины.
Переопределения одного запроса не изменяют настройки проекта.

`generation_parameters` и `generation_parameter_names` фиксируют параметры,
которые приложение задаёт при вызове модели. Параметры, не отправляемые
приложением (`temperature`, лимит ответа, `seed` и остальные), явно отмечены
как значения провайдера, неизвестные приложению. Приложение не утверждает,
что знает эти значения, и не разрешает использовать их как управляемые
оси сравнения. Их передача в JSON-запросе проекта, `/chat` или `/chat/generate`
отклоняется с HTTP 422 вместо игнорирования.

Для `generate` параметры поиска отсутствуют в действующих настройках и
списке осей сравнения. Наличие `top_k` в проекте не означает, что поиск
проводился. Режим каждого запуска сохранён отдельно.

## Журнал запусков

Для принятой попытки до обращения к внешним сервисам создаётся запись
`execution_runs` с идентификаторами проекта/сессии, режимом, статусом,
этапом и снимком настроек. После завершения записывается `success` либо `error`,
код ошибки и время завершения. Отклонённые запросы с ошибками валидации не
являются начавшимися запусками и не добавляются в журнал.

При обрыве процесса незавершённая запись может остаться `running`.
При анализе успешных запусков выбирайте только `status = 'success'`.
`running` и `error` не являются успешными ответами. Для подтверждения RAG
дополнительно проверяйте `details.retrieval_status = 'success'`.

Поле `details` содержит факт попытки генерации, размер контекста, число
сообщений и контрольную сумму подготовленного запроса, рассчитанную тем же
адаптером, который формирует вызов модели. Контрольная сумма проверяет
совпадение подготовленных параметров; она не подтверждает доставку запроса
провайдеру. Поле `response_trace` теперь содержит вопрос, ответ, найденные
фрагменты, фактический контекст и сообщения модели, время, токены, ошибки
и попытки. Подробнее — [полная информация об ответе](response-trace.md).
Дополнительных публичных адресов чтения журнала нет.

Снимок не изменяется после редактирования проекта. Запуск дополнительно
связан с неизменяемой версией конфигурации и выбранной версией индекса.
Изменение чанкинга или эмбеддера автоматически выбирает или строит отдельный
индекс из сохранённых версий файлов. Смена настроек поиска и генерации
использует готовый индекс повторно. Подробнее — [версии документов и индексов](versioning.md).

## Недоступные параметры

- Способы `sentences`/`tokens` не реализованы. `paragraphs` — фиксированное
  обозначение существующего рекурсивного алгоритма, а не отдельная ось сравнения.
- Доступна только стратегия `recursive`; сравнение стратегий исключено.
- Переключатель извлечения PDF-таблиц не реализован: допускается только `false`.
- Параметры генерации `temperature`, `max_tokens`, `seed` пока не настраиваются.

## Проверка и применение

Для существующей БД требуются миграции до `0006` включительно. Стандартная
инициализация backend применяет миграции при запуске; проверьте успешное
завершение миграции перед выполнением запросов.

Автоматические тесты проверяют оба режима, успешные и неуспешные попытки,
снимки после изменения проекта, переопределения одного запроса, контрольную
сумму фактических параметров и исключение ключей/URL-credentials из снимков.
Реальные модели и рабочая PostgreSQL требуют отдельной ручной проверки.

# Полная информация об ответе

Для каждого принятого запроса `/chat` и `/chat/generate` в
`execution_runs.response_trace` сохраняется цепочка выполнения. Идентификатор
`run_id` возвращается существующим API при успехе и технической ошибке.
Новых публичных адресов чтения журнала нет.

## Состав записи

| Поле | Значение |
| --- | --- |
| `schema_version` | Версия формата трассы: 1 |
| `question` | Вопрос этого запуска |
| `system_prompt` | Действующий системный промпт без добавленного контекста |
| `history` | Зафиксированная история, переданная при этом вызове |
| `retrieved_chunks` | Все результаты поиска в исходном порядке: `rank`, ID, полный текст, `score`, источник и метаданные |
| `document_version_id`, `document_sha256` у фрагмента | Ссылка на неизменяемую версию исходного файла и её SHA-256 |
| `context` | Фактический текст контекста после ограничения объёма |
| `context_chunk_ids` | Какие из найденных фрагментов вошли в контекст |
| `messages` | Подготовленные сообщения модели: системный промпт с контекстом, история и вопрос |
| `answer` | Ответ модели; при ошибке до получения ответа — `null` |
| `timings_ms` | Длительности этапов в миллисекундах |
| `attempts` | Отдельные записи каждой попытки: этап, номер, начало, статус, длительность, токены и ошибка |
| `errors` | Тип, очищенное сообщение, этап, номер попытки, HTTP-статус при наличии и возможность повтора |
| `retry_count` | Сколько дополнительных попыток выполнено после первых |
| `token_usage` | Последние известные данные каждого этапа; область действия явно указана как `last_attempt_per_stage` |
| `redaction_applied` | Найденные ключи или признаки credentials были заменены на `[REDACTED]` |

Состояние запуска, версия конфигурации и индекс хранятся в той же строке
`execution_runs`. Манифест индекса позволяет связать найденный фрагмент с
версией документа, его исходным именем, контрольной суммой и сохранённым файлом.

`retrieved_chunks = []` означает успешный поиск с пустой выдачей.
`retrieved_chunks = null` означает, что результаты поиска не получены или
поиск не применим. Для готового контекста режим отмечается как `generate`,
`retrieval_status = not_applicable`. Техническая ошибка retrieval отмечается
как `error` и останавливает генерацию.

Результаты поиска сохраняются целиком, даже если лимит контекста позволил
передать модели только первый фрагмент или его начало. Оценка поиска берётся
из ответа Qdrant; неизвестная оценка остаётся `null`.

## Время

Используется монотонный таймер. Записываются разрешение версии индекса,
подготовка/проверка индекса, эмбеддинг вопроса, поиск, сборка контекста и
генерация. Для неисполненных этапов длительности не выдумываются.

`attempts[].duration_ms` измеряет операцию попытки. Длительность этапа
в `timings_ms` включает его попытки, ожидание между повторами и работу журнала.
`total` — время до последнего обновления трассы, без сериализации HTTP-ответа
и завершения последней записи журнала. Это не отдельное измерение чистого
сетевого времени провайдера.

## Токены

При наличии ответа провайдера сохраняются `prompt_tokens`,
`completion_tokens`, `total_tokens` для генерации и эмбеддингов. Если доступны,
также сохраняются сведения о кешированных, reasoning-, audio- и prediction-токенах.
Отсутствующие счётчики остаются `null`; оценка по длине строки не подставляется.
Если провайдер сообщил настоящий ноль, он сохраняется как 0.

Расход записывается по каждой попытке. Сводное поле `token_usage` относится
только к последней попытке соответствующего этапа. Для стоимости всех попыток
нужно анализировать `attempts`: если расход хотя бы одной из них неизвестен,
полную стоимость нельзя считать известной. Например, неуспешное сетевое
обращение может иметь неизвестный расход, даже если последующая попытка
успешна и вернула счётчики.

При повторном использовании готового индекса эмбеддинги документов не
вычисляются: это отмечено в `details.index_reused`. `null` для этого этапа
не преобразуется в искусственный счётчик токенов.

## Ошибки и повторы

Оба маршрута принимают `max_attempts` от 1 до 3, по умолчанию 1.
Это максимум попыток каждого внешнего этапа, включая первую. Действующая
политика сохранена в конфигурации запуска. Например:

```json
{
  "question": "Какой код доступа к архиву проекта Север?",
  "max_attempts": 2
}
```

Повторяются сетевые сбои, таймауты, HTTP 429 и HTTP 5xx. Ошибки размерности,
неправильных параметров и другие невременные ошибки автоматически не повторяются.
Ожидание перед повторами — 100 и 200 мс. Встроенные повторы OpenAI SDK для
генерации и эмбеддингов отключены, чтобы попытки учитывались приложением явно.

Если поиск завершился успешно, а генерация упала, найденные фрагменты,
контекст и подготовленный запрос остаются в трассе. После исчерпания попыток
запуск получает статус `error`; успешный ответ в историю не добавляется.
Повторный HTTP-запрос создаёт новый `run_id` и сохраняет отдельную трассу.

## Ключи и исторические данные

В записи нет полей с API-ключами, заголовками авторизации или необработанным
ответом провайдера. Из текстов удаляются известные ключи проекта/окружения и
распознаваемые credential-поля, Bearer-токены и credentials в URL.
Очищаются также сохраняемые настройки, ошибки и новая история чата.

В обычном случае `messages` и `context` совпадают с переданными модели.
Если текст содержал ключ, приоритет имеет запрет хранения: сохраняется
очищенная версия с `redaction_applied = true`. Контрольная сумма подготовленного
запроса остаётся в `details.request_sha256`; сам секрет в очищенной трассе
не содержится. Не используйте её как побайтовую копию исходного запроса
при установленном признаке очистки.

Миграция `0006` добавляет nullable JSON-поле. Для старых запусков оно остаётся
`null`: отсутствующие данные и токены не восстанавливаются предположениями.
Стандартная инициализация backend применяет миграцию при старте.

## Проверка

123 backend-теста прошли, включая 16 проверок полной цепочки ответа,
токенов, очистки ключей и повторов. Проверены оба режима, успешные и ошибочные
запуски, сохранение контекста после ошибки LLM, порядок и оценки поиска,
частично известные счётчики и настоящий нулевой расход.

Для `0006` проверены PostgreSQL SQL и создание/откат поля на SQLite; старые
строки сохраняют `null`. Реальные провайдеры, сервер Qdrant и рабочая PostgreSQL
в этом прогоне не использовались.


Публичные сведения об ошибке содержат нейтральное сообщение, этап, тип исключения,
HTTP-код и признак возможности повтора. Исходный текст исключения не сохраняется
в новых трассах и публичных статусах загрузки; traceback остаётся в серверном журнале.
Доступ к журналам backend/worker должен быть ограничен на уровне развёртывания.
При чтении старых статусов загрузки и error_message источников также возвращается
нейтральное описание без исходного текста исключения.

# Анализ текущего состояния

Дата: **24 октября 2026 года**. Основание: исходники, схемы/миграции, тесты, Compose/Dockerfile, GitHub Actions и Jenkinsfile. Пользовательские документы не читались. Изменения задачи ограничены документацией.

## Итог

Есть связный прототип: управление проектами, UI загрузки документов, индексация, чат и SQL-история. Основные пробелы — работоспособность retrieval с текущими зависимостями, согласованность UI/API, жизненный цикл индекса, надёжность фоновых операций и защита ключей. Готовность к внешней эксплуатации не подтверждена.

## Реализовано и ограничено

| Область | Есть | Ограничение |
| --- | --- | --- |
| Проекты | CRUD API и Angular-страницы | Нет пользователей, авторизации и разграничения доступа |
| Документы | PDF с текстом, TXT, DOCX, ZIP | Нет OCR, HTML/CSV; UI предлагает неподдерживаемый MD |
| Чанкинг | Рекурсивное символьное разбиение | `split_by` и PDF `extract_tables` сохраняются без влияния на pipeline |
| Эмбеддинги | OpenAI-совместимый адаптер | HuggingFace — заглушка; размерность задаётся вручную |
| Индекс | Коллекция Qdrant на проект | Нет переиндексации, дедупликации и удаления по источнику |
| ZIP | BackgroundTasks и polling | Статусы в памяти, нет SQL-источников и сохранения оригиналов |
| Чат | Поиск, LLM, SQL-история | Поиск может упасть незаметно пользователю; контекст обрезается до 2000 символов |
| Celery | Worker и задача документа | Не вызывается HTTP-загрузками; явная регистрация модуля задач не настроена |
| Эксплуатация | Compose, CI, миграции при старте | Нет readiness зависимостей, согласованного backup и подтверждённого полного deployment |

## Приоритетные проблемы

Приоритеты — оценка последствий по коду, а не результаты security-аудита или нагрузочного теста.

| Приоритет | Факт и основание | Следующее действие |
| --- | --- | --- |
| Высокий | `core/vector_store/qdrant_store.py` вызывает `QdrantClient.search`; в установленном qdrant-client 1.17.1 такого метода нет | Адаптировать поиск и проверить интеграцией с Qdrant |
| Высокий | `api/chat.py` подавляет исключение retrieval и генерирует ответ без контекста | Явно сообщать сбой поиска и покрыть отказ тестом |
| Высокий перед внешним доступом | API без авторизации, `ProjectResponse` возвращает ключи, SQL хранит их строками | Контроль доступа, исключение ключей из ответов, защищённое хранение |
| Высокий | `api/data_sources.py` и `api/projects.py` удаляют только SQL | Связать точки с источниками, согласовать удаление файлов/векторов |
| Высокий | `api/upload.py` использует имя файла в пути, читает весь файл в память; собственных лимитов распаковки нет | Проверять конечные пути, нормализовать имена, ограничить объём/распаковку |
| Высокий для deployment | Нет prod `fileReplacements`, в Dockerfile неоднозначная команда сборки | Согласовать адрес API и сборку, проверить Compose с чистой установкой |
| Средний | UI показывает успешную карточку одиночной загрузки при HTTP 200, не учитывая `status: failed` | Расширить DTO и проверять статус результата |
| Средний | ZIP-операции в словаре процесса | Постоянное хранение операций и очередь с восстановлением |
| Средний | Схемы не проверяют overlap < size, часть настроек игнорируется | Межполевая валидация; реализация либо удаление недействующих настроек |
| Средний | Смена модели/чанкинга не перестраивает индекс; повторная загрузка добавляет точки | Версионирование индекса, переиндексация, идемпотентность |
| Средний | Startup подавляет ошибку БД, health всегда `ok` | Определить readiness и поведение при сбое миграций |
| Средний | Зависимости/версии разошлись между окружением, manifests и CI/Docker | Единый проверенный способ установки и фиксируемые версии |
| Средний | TestClient запускает реальный init_db; frontend проверяет подставной класс | Изолировать startup, добавить реальные UI/API и RAG-тесты |

Отсутствие метода `search` проверено локально через `hasattr`, без обращения к Qdrant. Следствие по коду: путь поиска не сможет выполнить этот вызов с установленной версией; широкий обработчик исключения допускает продолжение чата без контекста. Работа всего RAG-сценария внешними вызовами не проверялась.

## Результаты проверок

Окружение: Python 3.14.0 (`backend/.venv`), Node 24.13.0, pytest 9.0.3, pytest-asyncio 0.23.0, qdrant-client 1.17.1. Пакеты не устанавливались, рабочая БД и внешние LLM не использовались.

| Проверка | Результат |
| --- | --- |
| Обычный сбор backend-тестов с установленным asyncio-плагином | Ошибка `AttributeError: Package object has no attribute obj` |
| Изолированный синхронный backend-набор: init_db подменён, внешние embedding-тесты исключены, asyncio-плагин отключён | **26 passed**, два предупреждения |
| `npm test -- --run` | **2 passed**; только упрощённый класс, без реальных страниц |
| `npm run build` | **Успешно** после повторного запуска с сетевым доступом к Google Fonts |
| Полный Docker Compose, чистая установка, внешние эмбеддинги/LLM, реальные SQL/Qdrant | Не запускались |

Первый запуск frontend-тестов встретил ограничение доступа к временному файлу; повторный прошёл. Изолированный backend-прогон в ограниченной среде завис и был остановлен, повторный вне неё прошёл. Это ограничения среды проверки, отдельно от ошибки совместимости pytest-плагина. Команды изолированной проверки: [testing.md](testing.md).

## Рекомендуемый порядок развития

Сначала восстановить и проверить полный путь «загрузка → поиск → ответ с источниками», затем согласовать удаление/переиндексацию и фоновую обработку. Перед внешним доступом устранить открытые ключи и отсутствие авторизации. После этого расширять форматы, провайдеров и варианты чанкинга.

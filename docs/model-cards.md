# Model Card проекта

Во вкладке **Model Card** каждого проекта можно составить паспорт RAG-ассистента
по девяти разделам Google Model Cards, сохранить его версии и скачать Markdown
или Word. Вызов LLM для составления не требуется. Функция доступна и до загрузки
первого документа; при первом открытии проекта без карточек появляется черновик.

## Пользовательский сценарий

1. Создайте проект и задайте модели и параметры обработки документов.
2. Откройте **Model Card**. В новом проекте предпросмотр подготавливается автоматически.
3. Заполните назначение, аудиторию, предметную область, ответственного и известные
   сведения о базовой модели. Неизвестные сведения можно оставить пустыми:
   в карточке будет указано, что владелец их не заполнил.
4. При наличии проведённых измерений добавьте показатель, значение и единицу,
   размер выборки, набор данных, методику, дату и проверяющего. Нулевой результат
   допустим; отсутствие измерения не превращается в ноль.
5. Нажмите **Обновить предпросмотр**, затем **Сохранить версию**.
6. Сохранённую карточку можно читать, скачивать в Markdown/Word и использовать
   как основу следующей версии. Старая версия не перезаписывается.

Автоматический расчёт качества пока не подключён. `transport_stub` и оценки
близости Qdrant не считаются результатами качества. Ручные измерения явно
обозначены как введённые человеком; приложение не удостоверяет их достоверность.

## Содержание и происхождение данных

Карточка содержит разделы Model Details, Intended Use, Factors, Metrics,
Evaluation Data, Training Data, Quantitative Analyses, Ethical Considerations,
Caveats and Recommendations. Основа структуры:
[Mitchell et al., Model Cards for Model Reporting](https://arxiv.org/abs/1810.03993).

Автоматически подставляются модели, домены провайдеров, размерность эмбеддингов,
чанкинг, top_k, лимит контекста, отпечаток промпта, состав версий документов без
имён файлов и найденный в БД индекс. Значения относятся к настройкам проекта
и стандартному RAG-запросу: `score_threshold=null`, `max_attempts=1`.
Переопределения конкретных запросов, версии моделей за API-алиасами и параметры,
которые выбирает провайдер, автоматически не определяются.

Снимок хранит только разрешённые поля. API-ключи, userinfo, пути и параметры URL,
текст системного промпта, имена и содержимое файлов, вопросы, эталоны и диалоги
автоматически не включаются. Промпт и полные URL представлены SHA-256, чтобы
обнаруживать изменения без публикации исходных строк. Эти отпечатки не заменяют
шифрование. Ручные поля предназначены для публикуемого текста: не вставляйте в
них документы или диалоги целиком. Известные credentials в ручных полях
отклоняются; содержательная проверка персональных данных не выполняется.

Статус индекса берётся из SQL; создание карточки не читает исходные файлы,
не строит индекс и не проверяет доступность Qdrant. Источники старых установок
без версии документа отмечаются явно, без вымышленных контрольных сумм.

## Версии и актуальность

Каждое сохранение создаёт запись `model_card_versions` с последовательным номером,
снимком исходных данных, авторскими полями, измерениями и готовыми девятью
разделами. Отдельные SHA-256 фиксируют конфигурацию/состав документов и содержимое
карточки. Версия шаблона хранится в снимке; при изменении смысла шаблона её следует
повышать. Старые разделы не генерируются заново при чтении или экспорте.

Изменение названия, моделей, провайдеров, промпта, чанкинга, поиска, лимита контекста
или активного состава документов делает карточку исторической. API возвращает
`is_stale` и `changed_fields`, интерфейс показывает причину. При создании новой
карточки из устаревшей описание переносится, измерения очищаются в новом черновике.
Старые результаты остаются в прежней версии. Смена API-ключа и завершение построения
того же индекса сами по себе не меняют конфигурацию карточки.

Предпросмотр возвращает `source_sha256`. Сохранение проверяет, что конфигурация
не изменилась после предпросмотра, и требует ID последней сохранённой версии
`base_version_id` (для первой — `null`). Конфликт возвращает 409. Нумерация защищена
блокировкой строки проекта и уникальностью `(project_id, number)`. Параллельное
редактирование не перезаписывает чужую карточку.

Экспорт относится к сохранённому снимку и не подмешивает текущие настройки.
Markdown стабилен для одной версии; DOCX сохраняет тот же текст, но бинарная
идентичность ZIP-архивов между скачиваниями не гарантируется. В документе есть
дата, номер, отпечатки и напоминание сверить снимок с актуальным проектом.

## API

Базовый путь: `/api/v1/public/provider/projects/{project_id}/model-cards`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/preview` | Составить черновик без записи и внешних вызовов |
| POST | базовый путь | Сохранить новую неизменяемую версию |
| GET | `?offset=0&limit=25` | История, от новых к старым, до 100 версий на страницу |
| GET | `/{card_id}` | Полная версия и актуальность относительно проекта |
| GET | `/{card_id}/export?format=md` | Скачать Markdown |
| GET | `/{card_id}/export?format=docx` | Скачать Word |

Пример предпросмотра:

```json
{
  "context": {
    "intended_use": "Ответы по учебным регламентам",
    "users": "Студенты магистратуры",
    "owner": "Учебная команда"
  },
  "measurements": []
}
```

Для сохранения отправьте те же `context`/`measurements`, `source_sha256`
из предпросмотра и `base_version_id`. Неизвестные поля отклоняются.
Все операции ограничены проектом из URL; чужая версия возвращает 404.
Функция использует существующий режим доступа приложения, авторизация отдельно
не добавляется. Удаление проекта удаляет его карточки.

## Миграция и проверка

Добавлена миграция **0011**, следующая за 0010. Стандартный запуск backend применяет
миграции автоматически. Для ручного обновления из корня репозитория:

```bash
cd backend
poetry run alembic upgrade head
```

Новых зависимостей нет: Word собирается существующим `python-docx`.

```bash
poetry run pytest backend/tests/test_model_cards.py
poetry run pytest backend/tests --ignore=backend/tests/test_embeddings.py
cd frontend
npm test -- --run
npm run build
```

Тесты проверяют девять разделов, отсутствие записей/внешних вызовов при предпросмотре,
изменения моделей/промпта/данных, историю и конфликты, область проекта, очистку при
удалении, ручные результаты с нулём, нейтральный экспорт и миграцию туда/обратно.
Проверки интерфейса выполняются на настоящем Angular-компоненте и включают
устаревшие ответы предпросмотра, очистку прежних измерений, конфликт и скачивание.

При локальном падении нативного LMDB-кеша Angular можно проверить сборку командой
`CI=1 npm run build` (POSIX). Она отключает локальный кеш, не меняя конфигурацию
проекта. Реальные PostgreSQL и внешние AI-сервисы требуют отдельной интеграционной
проверки; составление карточки не зависит от доступности моделей.
